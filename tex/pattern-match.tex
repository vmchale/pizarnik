\section{Extensible Pattern Matches}

% mention Blume, Acar, Chae

Tags such as \verb|`true| are constructors, inspired by symbols (\verb|`blue|) in k (preceded by symbols \verb|'red| in Lisp). \verb|`true| has type \verb|-- `true|. It can also be said to have type $-- \{ \mathtt{`true}~\oplus~\mathtt{`false} \}$. To see why we would wish to admit $\mathtt{`true}~\oplus~\mathtt{`false}$, consider

% even then, we should only generalize on the left.
% negative polarity <-> "left permeable"
% insisting on specificity on the right=pattern-match exhaustiveness checking

\begin{verbatim}
type Bool = { `true ⊕ `false };

not : Bool -- Bool
    := [ { `false⁻¹ `true & `true⁻¹ `false } ]
\end{verbatim}

\verb|`false⁻¹| has type \verb|`false --| and hence \verb|`false⁻¹ `true| has type \verb|`false -- `true|; \verb|`true⁻¹ `false| has type \verb|`true -- `false|.
% inverse type exchanges sides (sequent calculus/linear logic) `true⁻¹ : `true --
% true inverse

Perhaps counterintuitively, we get pattern-match exhaustiveness checking for free. $\oplus$ is a disjunction and thus we may generalize as we see fit, but $\&$ is a conjunction; it restricts\footnote{$\&$ is a product; it would be farcical for a programmer to supply \verb|1| when a term of type \verb|(Int * Int)| is required. Yet this is exactly what allowing inexhaustive and redundant pattern matches encourages!}.

To invert a sum type, we supply a product of its inverses (pattern match clauses). This is precisely the de Morgan laws.

\subsection{Reusing Pattern-Match Arms}

We can define a function

\begin{verbatim}
if : a a `true -- a
   := [ { `true⁻¹ drop } ]
\end{verbatim}

This is not so useful on its own---it requires the programmer to supply exactly one value and then discards it---but see how it unifies:

\begin{verbatim}
else : a a `false -- a
     := [ { `false⁻¹ nip } ]

choice : a a Bool -- a
       := [ { if & else } ]
\end{verbatim}

Pattern-match arms are terms like builtin functions \verb|+| etc. and can be reused (referenced); one enjoys cut elimination for sequences of such.

\subsection{Typesafe Head}

\begin{verbatim}
type List a = { `nil ⊕ List(a) a `cons };

type NE a = { List(a) a `cons };

head : NE a -- a
     := [ { `cons⁻¹ nip } ]
\end{verbatim}

Any nonempty list can be supplied as an argument to a function on lists. This is far more tolerable than the situation in Haskell, in which \verb|foldr| \&c. must be defined for \verb|NonEmpty| and \verb|List| separately.

\subsection{Or-Patterns}

Suppose we have

\begin{verbatim}
type Ord = { `lt ⊕ `eq ⊕ `gt };
\end{verbatim}

Then we can define

\begin{verbatim}
gt : Ord -- Bool
      := [ { { `lt⁻¹ & `eq⁻¹ } `false & `gt⁻¹ `true } ]
\end{verbatim}

or

\begin{verbatim}
lte : { `lt ⊕ `eq } --
    := [ { `lt⁻¹ & `eq⁻¹ } ]

gt : Ord -- Bool
      := [ { lte `false & `gt⁻¹ `true } ]
\end{verbatim}

So we get or-patterns and they are reusable as functions.
