Pizarnik's approach to pattern-matching is based on commitment to the idea of pattern-matching as inverse\cite{ehrenberg2009} and suggestive notation from linear logic ($\&$, ``with'', is dual to disjunction, $\oplus$) \cite{munchmaccagnoni}.

\section{Extensible Pattern Matches}

Suppose we define an algebraic data type

\begin{verbatim}
type Bool = { `true ⊕ `false };
\end{verbatim}

The literal \verb|`true| pushes a tag\footnote{Inspired by symbols (e.g. \verb|`blue|) in k, which are preceded by symbols (\verb|'red|) in Lisp.}  \verb|`true| onto the stack. We assign it the type \verb|-- `true|. Its inverse \verb|`true⁻¹| pops a value of type \verb|`true| off the stack and hence the atom \verb|`true⁻¹| has type \verb|`true --| (inverse exchanges left and right).
% negation as fruitful interaction (orthogonality) rather than situation with principle of explosion we have in classical logic

In linear logic, one has $(G\oplus H)^\bot = G^\bot \& H ^\bot$. To pop off a value of type \verb|Bool = { `true ⊕ `false }|, one writes \verb|{ `true⁻¹ & `false⁻¹ }| in Pizarnik. Or-patterns in other programming languages work like linear logic's \verb|&|, which identifies a product of deconstructors into a deconstructor for a sum---the De Morgan laws.

\subsection{Reusing Pattern-Match Arms}

We can define a function

\begin{verbatim}
if : a a `true -- a
   := [ { `true⁻¹ drop } ]
\end{verbatim}

This is not so useful on its own---it requires the programmer to supply exactly one value and then discards it---but see how it unifies:

\begin{verbatim}
else : a a `false -- a
     := [ { `false⁻¹ nip } ]

choice : a a Bool -- a
       := [ { if & else } ]
\end{verbatim}

Pattern-match arms are terms like builtin functions \verb|+| etc. and can be reused (referenced); one enjoys cut elimination for sequences of such.

\subsection{Typesafe Head}

\begin{verbatim}
type List a = { `nil ⊕ List(a) a `cons };

type NE a = { List(a) a `cons };

head : NE a -- a
     := [ { `cons⁻¹ nip } ]
\end{verbatim}

Any nonempty list can be supplied as an argument to a function on lists. This is far more satisfactory than the situation in Haskell, in which \verb|foldr| \&c. must be defined for \verb|NonEmpty| and \verb|List| separately.

\subsection{Or-Patterns}

Suppose we have

\begin{verbatim}
type Ord = { `lt ⊕ `eq ⊕ `gt };
\end{verbatim}

Then we can define

\begin{verbatim}
lte : { `lt ⊕ `eq } --
    := [ { `lt⁻¹ & `eq⁻¹ } ]

gt : Ord -- Bool
      := [ { lte `false & `gt⁻¹ `true } ]
\end{verbatim}

So or-patterns are reusable as functions.
