\section{Introduction}

Pizarnik's approach to pattern-matching is based on commitment to the idea of pattern-matching as inverse\cite{ehrenberg2009} and suggestive notation from linear logic ($\&$, ``with'', is dual to disjunction, $\oplus$) \cite{munchmaccagnoni}.

\section{Extensible Pattern Matches}

Suppose we define an algebraic data type

\begin{verbatim}
type Bool = `true ⊕ `false;
\end{verbatim}

The literal \verb|`true| pushes a tag\footnote{Inspired by symbols (e.g. \verb|`blue|) in k, which are preceded by symbols (\verb|'red|) in Lisp.}  \verb|`true| onto the stack. We assign it the type \verb|-- `true|. Its inverse \verb|`true⁻¹| pops a value of type \verb|`true| off the stack and hence the atom \verb|`true⁻¹| has type \verb|`true --| (inverse exchanges left and right).

% negation as fruitful interaction (orthogonality) rather than situation with principle of explosion we have in classical logic
% sorta makes sense that we get pattern-match exhaustiveness checking
% also left-right, exactly at beta-reduction... which is no doubt a fruitful interaction!

In linear logic, one has $(G\oplus H)^\bot = G^\bot \& H ^\bot$. To pop off a value of type \verb|Bool = { `true ⊕ `false }|, one writes \verb|{ `true⁻¹ & `false⁻¹ }| in Pizarnik. Or-patterns in other programming languages work like linear logic's \verb|&|, which identifies a product of deconstructors with a deconstructor for a sum---the De Morgan laws. % emphasizes duality

Taking \verb|not : Bool -- Bool|, we say

$$\mathtag{true}~\mathtt{not} : -- \mathtt{Bool}$$

\verb|`true| has type \verb|-- `true| which can be generalized to $--\mathtag{true}\oplus\mathtag{false}$ (an acceptable argument to \verb|not : Bool -- Bool|). Sum types generalize but \textit{only on the right}. This realizes the situation in linear logic \cite{ll}[p.~102].

\begin{mathpar}
\inferrule
{\Gamma;\Gamma'\vdash \Delta';\Delta,A}
{\Gamma;\Gamma'\vdash \Delta';\Delta,A \oplus B}
\quad(\mathcal{R}1\oplus)

\inferrule
{\Gamma;\Gamma'\vdash \Delta';\Delta,B}
{\Gamma;\Gamma'\vdash \Delta';\Delta,A \oplus B}
\quad(\mathcal{R}2\oplus)

\inferrule
{A,\Gamma;\Gamma'\vdash\Delta';\Delta \\ B,\Gamma;\Gamma'\vdash\Delta';\Delta}
{A\oplus B,\Gamma;\Gamma';\vdash \Delta'\Delta}
\quad(\mathcal{L}\oplus)

\inferrule
{\Gamma;\Gamma'\vdash \Delta';\Delta,A \\ \Gamma;\Gamma'\vdash\Delta';\Delta, B}
{\Gamma;\Gamma'\vdash\Delta';\Delta,A \& B}
\quad(\mathcal{R}\&)
\end{mathpar}

\subsection{Reusing Pattern-Match Arms}

We can define a function

\begin{verbatim}
if : a b `true -- a
   := [ { `true⁻¹ drop } ]
\end{verbatim}

This is not so useful on its own---it requires the programmer to supply exactly one value and then discards it---but see how it unifies:

\begin{verbatim}
else : a b `false -- b
     := [ { `false⁻¹ nip } ]

choice : a a Bool -- a
       := [ { if & else } ]
\end{verbatim}

Pattern-match arms are terms like builtin functions (\verb|+|, \verb|swap|, etc.) and can be reused (named); one enjoys cut elimination for sequences of such.

\subsection{Typesafe Head}

\begin{verbatim}
type List a = { `nil ⊕ List(a) a `cons };

type NE a = { List(a) a `cons };

head : NE a -- a
     := [ { `cons⁻¹ nip } ]
\end{verbatim}

Any nonempty list can be supplied as an argument to a function on lists. This is far more satisfactory than the situation in Haskell, in which \verb|foldr| \&c. must be defined for \verb|NonEmpty| and \verb|List| separately.\footnote{Typeclasses allow \verb|foldr| to be called on non-empty lists and lists equally but instances must be defined separately, and the typeclass machinery brings globality of instances and other complications.}

\subsection{Pattern Terms}

Suppose we have

\begin{verbatim}
type Ord = { `lt ⊕ `eq ⊕ `gt };
\end{verbatim}

Then we can define

\begin{verbatim}
lte : { `lt ⊕ `eq } --
    := [ { `lt⁻¹ & `eq⁻¹ } ]

gt : Ord -- Bool
      := [ { lte `false & `gt⁻¹ `true } ]
\end{verbatim}

So or-patterns are reusable, enjoy cut-elimination, etc.
